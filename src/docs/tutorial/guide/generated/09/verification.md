# Verification

Each check catches a different kind of mistake. None of them catches everything, so the design system relies on all five.

| Check         | Command                                      | What it proves                                                                                                                                                                                                                                                                                    | Misses                                                                            |
| ------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Types         | `npm run typecheck`                          | Removed variant values written in place; missing required props (an icon button without a name)                                                                                                                                                                                                   | Values that arrive as a plain `string`, type assertions, anything about behaviour |
| Lint          | `npm run lint`                               | Restyling, raw elements, implementation imports, variant values against `crease.lock.json`, the product import rule                                                                                                                                                                               | Whether the app does the right thing                                              |
| Lint fixtures | `npm run check:lint-fixtures`                | That the lint itself still rejects what it should (and accepts placement), after a lint or config change                                                                                                                                                                                          | Everything outside the lint                                                       |
| Tests         | `npm test`                                   | update: commits, saves, validation, drafts, team assignment, the issue page, shortcuts, the theme switch, and every Command each step produces                                                                                                                                                    | Layout, focus in a real DOM, CSS                                                  |
| Browser       | `npm run check:browser` (with `npm run dev`) | Rows on one line at 900px and on a phone, same row everywhere, pickers with focus return, the composer, reload, failed and unreadable storage, team pages and saved views, the issue page, Ctrl+K and C, the dark theme including the sidebar, and component guarantees on `component-check.html` | Code paths it does not click through                                              |

`npm run check` runs the first four. The browser check needs the running app.

## Known gaps, found by breaking the app on purpose

The guide's chapter 9 applied eight regressions and recorded which check failed for each. One passed every check: removing `whitespace-nowrap` from `item`'s inline layout. Measuring showed why. Since chapter 7 every list uses `IssueRow`, which puts the identifier outside the row's content, so no text in today's app wraps without that class. It protects a pattern that puts text into the content, which the app does not have yet.

A guarantee of a component is tested at the component. `component-check.html` renders `item` with text in its content in a 240px column, and the browser check measures it; with the class removed it fails. The browser check also measures search results on a 480px screen.
